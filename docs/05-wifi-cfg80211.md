# 05 — El crash de WiFi (cfg80211) y los 12 bytes

## El sintoma
Con el switch prendido, `ip link set eth1 up` **colgaba el equipo entero**: la
consola echoaba pero no ejecutaba nada, `sysrq` muerto. Un stall duro, no un
panic. Y ningun `printk` de instrumentacion disparaba — el cuelgue era *antes*
del `ndo_open` del puerto.

## La pista: siempre 12 bytes
```
list_add corruption. prev->next should be next (c167700c), but was c1677000.
... otro boot: c167380c vs c1673800   ... otro: c167100c vs c1671000
```
La diferencia es SIEMPRE `0xC` = **12 bytes**. Un `struct` corrido 12 bytes.

El call trace apuntaba a `cfg80211_netdev_notifier_call` (modulo de WiFi), no al
switch.

## La causa raiz
`cfg80211` registra un netdevice notifier al cargar; Linux lo re-ejecuta para
cada interfaz. Para un eth cableado deberia salir en la primera linea:
```c
struct wireless_dev *wdev = dev->ieee80211_ptr;
if (!wdev) return NOTIFY_DONE;      // un eth cableado sale aca
...
guard(wiphy)(&rdev->wiphy);          // ...pero llegaba hasta aca -> mutex basura
```

En **Linux 6.18**, el campo `ieee80211_ptr` de `struct net_device` dejo de
gatearse con `CONFIG_CFG80211` y paso a `CONFIG_CFG80211_HEADERS` (simbolo
nuevo, ya upstream). Como OpenWrt provee `cfg80211` por el **backport** (no
in-tree), si el **vmlinux** se compila SIN `CFG80211_HEADERS` -> `net_device`
queda SIN el campo, mientras el **modulo** cfg80211.ko lo tiene. Dos vistas del
mismo struct, descuadradas. `dev->ieee80211_ptr` lee basura no-NULL ->
`wdev` basura -> mutex basura -> `list_add corruption`.

Y con `CONFIG_MODVERSIONS` apagado (como en OpenWrt), un modulo compilado
contra otra config de `net_device` **carga igual, sin chequeo, y corrompe en
silencio**.

## El fix (dos piezas, ambas necesarias)
1. `CONFIG_CFG80211_HEADERS=y` **+ rebuild LIMPIO del kernel**
   (`make target/linux/clean`). Los rebuilds incrementales no recompilan
   `net/core/dev.c` -> el vmlinux queda stale sin el campo.
2. **Recompilar los modulos contra ese kernel exacto**:
   ```sh
   make package/kernel/mac80211/{clean,compile}
   make package/kernel/mt76/{clean,compile}
   ```
   y poner los `.ko` frescos en el rootfs.

Con eso: `list_add corruption` = 0, `cfg80211`/`mac80211`/`mt7915e` cargan,
`/sys/class/ieee80211/` muestra `phy0` + `phy1` (HE80 = Wi-Fi 6).

> Gotcha del build: `make target/linux/clean` regenera el `.config` y vuelve a
> perder `CMDLINE_FORCE` (el `choice` resuelve a `FROM_BOOTLOADER`). Hay que
> reaplicarlo / dejar los disables en el config fragment.
